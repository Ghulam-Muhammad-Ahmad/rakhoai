C1. Service Role Key Exposed to Client-Side Bundle
src/lib/db/client.tsSecurity
Fixed
›

The db client uses SUPABASE_SERVICE_ROLE_KEY which bypasses ALL Row Level Security. The global singleton pattern combined with Next.js bundling could accidentally expose this to client bundles if any component transitively imports from @/lib/db/client.

// Line 6: Service role key — bypasses ALL RLS const key = process.env.SUPABASE_SERVICE_ROLE_KEY;
Fix

Add import "server-only" at the top of the file, or use Next.js's server-only package to prevent client-side bundling.

Final Verdict

This app is vibe coded. Built rapidly with AI agents, it demonstrates the classic pattern:

  1. Works for the happy path — core flow (upload → map → score → display) functions
  2. Breaks under edge cases — race conditions, error handling, security are afterthoughts
  3. Type safety is an illusion — 40+ as any casts
  4. Architecture evolved organically — two scoring pipelines, dead code
  5. Security is surface-level — auth checks exist but rate limiting and input validation missing
  6. No testing discipline — critical paths have zero coverage

Before production: Security audit, consolidate pipelines, remove as any, add tests, error boundaries, align PRD with reality.
